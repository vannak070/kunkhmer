## What staff get
- **KKF ID** for every fighter (`KKF-000123`): the next number shows while registering; KKF staff (Super Admin, KKF Officer) can change it
  (`KKF-` + 4–12 digits, must be unique); clubs see it read-only. It also shows on the fighter page, the Fighters list and the header search.
- **Personal and medical details are optional** when registering a fighter ("Missing details" warnings stay as a reminder).
- **Duplicate protection**: the same ID / passport number cannot be saved for two fighters (spaces, dashes, dots and capitals don't matter);
  the same Khmer name + date of birth is refused with a link to the existing fighter; similar names stay a warning.
- **Merge into another fighter** (fighter page › "⋯"): moves bouts, results, titles, videos, fan follows and private details to the fighter you keep,
  recalculates the record, removes the duplicate. Staff only. **There is no undo** (the log keeps who, when and counts).
- **Fighters › Duplicates** (KKF staff): pairs in two tiers (*Very likely* / *Possible*), "Keep this one — merge the other into it", "Not the same person"
  (remembered, with a Dismissed tab).
- **Fighter pickers** ask the server (Add bout, Add several bouts, Draw, replacement panel, Video, Create title) — nothing downloads the whole fighter list any more.
- **Home page**: the partner box shows sponsors only (no broadcasters / international partners) and says "Official sponsors".

## Things that change on the live data (read once)
1. Migration `20261014160000_fighter_kkf_id` **numbers every existing fighter** `KKF-000001…` by registration date and gives new fighters the next number
   automatically (database default; the numbers are never reused). The live site has no fighters yet; if staff register some before the update, they are numbered in order.
2. Existing fighters with the same ID number twice are not changed; the next save of either is refused until one is fixed or merged (none on the live site today).
3. The first KKF ID on a fresh counter is `KKF-000001`; a number staff type by hand that is higher does not move the counter (the generator skips taken numbers).
4. The Duplicates menu item is for KKF staff only (permission `fighters.duplicates`).

## Before you start (5 minutes)
1. Make a **DigitalOcean snapshot** of the droplet (recommended).
2. Choose a quiet time: the site is unavailable for about 30–60 seconds while the backend restarts (the build does not stop it).
3. Be ready to copy `deploy/backups/` to your computer afterwards (the update makes a fresh backup first).
4. If you will edit docs in git first, deploy the commit you pushed last (`<COMMIT>`); otherwise use `bb5a146c`.

## Deploy (on the server)
```bash
ssh root@104.248.149.103
cd /root/kunkhmer/deploy
git rev-parse --short HEAD                               # the version running now — expect 936db4ea (write it down)
git fetch origin dev && git checkout --detach bb5a146c   # fetches update.sh / preflight.sh; the running site is not touched yet
sh preflight.sh                                          # read-only: memory, disk, backups, data counts, API
sh update.sh bb5a146c 936db4ea                           # backup → build backend → build web → start → wait for API
```
`update.sh` stops at the first error and leaves the old version running until the last step (`up -d`). It prints the migrations it applied and the rollback
command. The "Data now" line from `preflight.sh` (users / clubs / fighters / migrations) must be the same afterwards, with the migration count **39 → 43**.
If the `npm` step stops with `ECONNRESET` (network), run `sh update.sh bb5a146c 936db4ea` again.

## Rollback
- **Fast (keeps data):** `git checkout --detach 936db4ea && COMPOSE_PARALLEL_LIMIT=1 docker compose -f docker-compose.prod.yml up -d --build` — the old version runs on the new database
  (KKF IDs and merge/dismissal tables stay but are ignored). Merged fighters stay merged.
- **Full restore (exact data before the update):** `sh restore.sh backups/db_<time of the update backup>.dump` (README section 5). Note this also undoes anything entered after the backup.
- **Last resort:** the DigitalOcean snapshot.
