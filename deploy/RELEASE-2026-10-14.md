## Before you start (5 minutes)
0. **Put this package in git.** `deploy/RELEASE-2026-10-14.md`, `deploy/preflight.sh`, `deploy/update.sh` and the edited `deploy/README.md` are new / changed and not committed yet.
   Commit and push them to `dev` (only those four files), then on your Mac run `git rev-parse --short HEAD` — that is `<COMMIT>`. Nothing else differs from
   `936db4ea`, so the tested code is what gets deployed.
1. **Make a DigitalOcean snapshot** of the droplet (Droplet → Snapshots) — the safest undo. (Optional but recommended.)
2. **Memory.** The droplet has about 1 GB. Run `sh preflight.sh` (below) and look at `free -m`: if memory + swap free is under ~1.5 GB, add swap first:
   ```bash
   fallocate -l 2G /swapfile && chmod 600 /swapfile && mkswap /swapfile && swapon /swapfile
   ```
   (Builds then take longer but finish. When the server is upgraded to 2 GB this is not needed.)
3. **Choose a quiet time.** The site is unavailable for about 30–60 seconds while the backend restarts; the build itself does not stop the site.
4. Be ready to copy `deploy/backups/` to your computer afterwards (backups so far live only on the server).

## Deploy (on the server)
```bash
ssh root@104.248.149.103
cd /root/kunkhmer/deploy
git rev-parse --short HEAD                               # the version running now — expect 03a5f440 (write it down)
git fetch origin dev && git checkout --detach <COMMIT>   # gets the two scripts (the running site is not touched yet)
sh preflight.sh                                          # read-only: memory, disk, backups, data counts, API
sh update.sh <COMMIT> 03a5f440                           # backup → build backend → build web → start → wait for API
```
`update.sh` stops at the first error and leaves the old version running until the very last step (`up -d`). It prints the migrations it applied and the
exact rollback command. Write down the "Data now" line from `preflight.sh` (clubs / users / migrations) — it must be the same after the update, with the
migration count 14 higher (**25 → 39**).

If the `npm` step stops with `ECONNRESET` (network), just run `sh update.sh <COMMIT> 03a5f440` again.

**Without the scripts** (same thing by hand): `docker compose -f docker-compose.prod.yml exec backup sh /backup.sh now` →
`git fetch origin dev && git checkout --detach <COMMIT>` → `COMPOSE_PARALLEL_LIMIT=1 docker compose -f docker-compose.prod.yml build backend` →
the same with `build web` → `docker compose -f docker-compose.prod.yml up -d` → `docker compose -f docker-compose.prod.yml logs -f backend`.

## Rollback
- **Fast (keeps data):** the old version runs on the new database. On the server:
  `git checkout --detach 03a5f440 && COMPOSE_PARALLEL_LIMIT=1 docker compose -f docker-compose.prod.yml up -d --build`
  (the new tables and columns stay but are ignored).
- **Full restore (back to the exact data before the update):** `sh restore.sh backups/db_<time of the update backup>.dump` (README section 5). The update
  backup is the newest `db_…dump` created at the start of `update.sh`.
- **Last resort:** restore the DigitalOcean snapshot.
